This page is written for **tournament operators**. It focuses on what you’ll see in the MAT UI and what to do next.

## Plugin DB DOWN

If MAT shows **“Plugin DB DOWN”**, it means:

- the MatchZy Enhanced plugin **cannot connect to its database**

This is **not** MAT’s Postgres database. It’s the database used by the MatchZy plugin on the CS2 server host (often a MySQL container when using CSM).

### Fix (CSM-managed MatchZy DB)

If you installed servers with **CS2 Server Manager (CSM)**, the easiest fix is:

1. Run `sudo csm`
2. Go to **Tools**
3. Select **“MatchZy DB: verify/repair”**

This runs CSM’s built-in verifier/repair flow, which checks the MatchZy database container/user/database and recreates what’s missing.

Then refresh the server status in MAT (Servers page).

### Fix (external MatchZy DB)

If you use an external DB (no Docker provisioning), verify:

- the MatchZy DB config file is correct on the server host: `/home/<cs2user>/overrides/game/csgo/cfg/MatchZy/database.json` (see: **[CSM Configuration & overrides](/docs/csm/user/configuration)**)
- the DB host/port is reachable from the server host
- credentials and permissions are correct

You can still open `sudo csm` → **Tools** → **MatchZy DB: verify/repair** to get a helpful, human-readable diagnosis, but note:

- if you’re using an external DB, you must ensure CSM is configured to **not** provision a Docker DB (for example via a “skip docker DB” setting in your environment), otherwise it will assume the Docker-based workflow.

Then refresh the server status in MAT (Servers page).

## CS2 update required

This means Valve released a CS2 update and **one or more servers are behind**.

MAT will block outdated servers from new allocations (and may block tournament start until your enabled fleet is up to date).

### Fix

If you use **CS2 Server Manager (CSM)**, update game files and restart:

- `sudo csm update-game`
- `sudo csm restart` (or restart the specific server)

If you update manually (no CSM), make sure the server is fully updated via SteamCMD and restarted.

Then refresh the server status in MAT (Servers page) and try again.

## Server offline or unreachable

If MAT shows **Offline** / **RCON failed** / **Server can’t reach MAT**, it usually means one of these:

- **MAT → server unreachable (RCON)**: wrong host/port/password, firewall, server not running
- **Server → MAT unreachable (webhook)**: the game server can’t reach MAT’s webhook URL (egress/DNS/reverse-proxy URL mismatch)
- **No events yet**: MAT sent config, but MatchZy never called back (often webhook reachability or MatchZy not loaded)

### Fix checklist

- Verify the server is running (if using CSM: `sudo csm status`, then `sudo csm attach <server>` for logs)
- Verify `rcon_password` and port mapping/firewall allow RCON from MAT to the server host
- Verify the server host can reach MAT’s API URL (DNS + outbound connectivity)
- If you changed domains/ports, re-run initialization (Servers page → Retry)

Then refresh the server status in MAT (Servers page).

## IP banned (RCON)

If MAT shows **IP Banned**, the server has temporarily banned MAT’s IP due to repeated RCON authentication failures.

### Fix

1. Fix the RCON password in MAT (Servers page) so MAT stops retrying with a bad password.
2. Unban the IP on the server side.

If you use CSM, you can use its CLI helpers:

- `csm list-bans <server>`
- `sudo csm unban-all <server>` (or unban a specific IP: `sudo csm unban <server> <ip>`)

Then refresh the server status in MAT (Servers page).

## Plugin version mismatch

If MAT shows **Version Mismatch**, your server fleet is running different MatchZy Enhanced plugin versions.

### Fix

If you use CSM:

- `sudo csm update-plugins`
- restart servers (`sudo csm restart` or `sudo csm restart <server>`)

If you update manually, install the same MatchZy Enhanced release on every server and restart them.

Then refresh the server status in MAT (Servers page).
