Manual installation guide for setting up CS2 servers with the enhanced MatchZy plugin.

> Recommended: Use CS2 Server Manager for automated setup. It installs everything you need with one command.

## Prerequisites

### Install CounterStrikeSharp

Follow the official CounterStrikeSharp getting started guide: [Getting Started](https://docs.cssharp.dev/docs/guides/getting-started.html)

After completing the guide:

- Verify **Metamod** is installed (server console):

```text
meta list
```

If CounterStrikeSharp is installed correctly, you can also verify it with:

```text
css_plugins list
```

## Install MatchZy Enhanced

> Important: This project requires an enhanced fork of MatchZy that emits additional events used for automation.

### Download

- Latest release: [MatchZy-Enhanced releases](https://github.com/sivert-io/MatchZy-Enhanced/releases/latest)
- Docs: [MatchZy Enhanced docs](/docs/me)

### Install

```bash
cd /path/to/cs2/game/csgo
unzip MatchZy-*.zip
```

Restart your CS2 server.

### Verify

Type `css_plugins list` in server console. You should see MatchZy listed.

## Configure RCON

Add these to your server's `autoexec.cfg` or `server.cfg`:

```ini
rcon_password "your-secure-rcon-password"
hostport 27015
```

## Connect the server to MAT

Once the server can be reached by RCON, add it in MAT under **Servers**.

MAT configures MatchZy Enhanced automatically. Newer versions use a **bootstrap URL** so the server can pull a single payload and persist it locally (instead of MAT pushing many separate RCON commands).

MAT’s initialization sets a small number of RCON values:

- `matchzy_server_id`
- `matchzy_bootstrap_url`
- `matchzy_bootstrap_token`

The MatchZy plugin then fetches `GET /api/servers/:id/bootstrap`, applies the returned `commands[]`, and persists them in its own DB.

This is used to configure (webhook URL, demo upload URL, auth headers, core defaults, etc.) when:

- The server is initialized, and
- Matches are loaded on that server

Make sure MAT has:

- A configured **Webhook URL** in **Settings**
- `SERVER_TOKEN` set in MAT’s `.env` (used as the `X-MatchZy-Token` header for demo uploads and server-to-MAT requests)

## Configure webhook reachability

Your CS2 server must be able to reach the MAT API.

```bash
curl http://your-tournament-ip:3069/api/events/test
```

Should return something like:

```json
{ "success": true, "message": "events route is working" }
```

## CS2 updates (auto-updater + admin warning)

MatchZy Enhanced includes a **MatchZy-safe update checker**: it checks Steam for CS2 updates while avoiding live matches.

By default (MAT-oriented), it is **warn-only**: it emits markers/events so your external server manager/admin can update/restart servers on your schedule. Automatic quitting can be enabled explicitly.

When an update is required, MatchZy Enhanced will:

- Log markers in the server console:

```text
[MATCHZY_UPDATE_AVAILABLE] required_version=<number>
[MATCHZY_UPDATE_SHUTDOWN] required_version=<number>
```

- Send a webhook event to MAT (if `matchzy_remote_log_url` is configured):

```json
{
  "event": "cs2_update_required",
  "matchid": -1,
  "server_id": "s_1",
  "required_version": 14134,
  "phase": "available",
  "timestamp": 1769805517
}
```

In the MAT admin UI, the **Servers** page will show a large warning when any server reports this.

### MAT Steam verification (no waiting for plugin event)

MAT can also verify CS2 build freshness directly by:

- Fetching the installed CS2 **BuildID** via RCON `version`
- Checking Steam `ISteamApps/UpToDateCheck`

This is used to block allocation to out-of-date servers even if the plugin has not emitted `cs2_update_required` yet, and MAT performs a final preflight check when starting a tournament.

### Fixing “CS2 update required”

Update the server installation (e.g. SteamCMD / your host manager) and restart the server. When the server comes back up and sends `server_configured` (Startup), MAT clears the stale warning.

## Plugin database health (admin warning)

MatchZy Enhanced uses SQLite or MySQL to store:

- Server config (persistent MatchZy settings)
- Backup metadata and match stats
- Event retry queue (reliable delivery)

If the plugin cannot reach its DB, it will still run matches, but **backups and reliable event delivery may be impacted**.

MatchZy Enhanced reports this to MAT via `event=server_health` (server-level webhook), and MAT shows:

- A per-server **“Plugin DB DOWN”** chip on the Servers page
- A **persistent global warning** while any enabled server reports DB down

### Fixing “Plugin DB DOWN”

Check the CS2 server logs (MatchZy output) and validate:

- `cfg/MatchZy/database.json` is correct
- MySQL is reachable from the game server host (firewall/DNS/user/password)
- The DB user has permissions and the database exists

## Network configuration notes

- Docker setup typically exposes MAT on port **3069**
- Local dev uses port **3000** for the API
