This page is written for **tournament operators**. The goal is simple: get servers online, add them to MAT, and make sure they can talk to each other.

## Recommended setup (CSM)

If you’re running more than one server, use **CS2 Server Manager (CSM)**. It installs CS2, MatchZy Enhanced, and keeps things consistent.

1. Install and run CSM: **[CSM quick start](/docs/csm/quick-start)**
2. In MAT, go to **Servers** and add your servers (host/port/RCON).
3. Wait for each server to go green/healthy.

If you see warnings, use: **[Server health (common warnings)](/docs/mat/user/fleet-health)**.

## Manual setup (advanced)

Use this only if you are not using CSM.

### 1) Install prerequisites on the CS2 host

- Install Metamod + CounterStrikeSharp (CSS)
- Install MatchZy Enhanced (so it appears in `css_plugins list`)

MatchZy Enhanced docs: **[/docs/me](/docs/me)**

### 2) Configure RCON (MAT → server)

Set a correct RCON password and port in your server config:

```ini
rcon_password "your-secure-rcon-password"
hostport 27015
```

Then, in MAT → **Servers**, add the server with the same host/port/password.

### 3) Verify webhook reachability (server → MAT)

Your CS2 host must be able to reach the MAT API. From the CS2 host:

```bash
curl http://your-mat-host:3069/api/events/test
```

You should see:

```json
{ "success": true, "message": "events route is working" }
```

If this fails, fix DNS/firewall/reverse-proxy first.

## Several servers, one MatchZy database

Several CS2 servers can share one MatchZy MySQL database. Use MatchZy-Enhanced **1.4.28** or newer on every server.

Older versions stored the plugin's saved settings (server ID, bootstrap URL, tokens) once per database instead of once per server. Servers sharing a database overwrote each other's settings, so after a restart they all reported the same server ID and MAT saw one server several times. Since 1.4.26 each server keeps its own settings, 1.4.27 fixed how the plugin tells servers apart, and 1.4.28 fixed a first configure that could fetch another server's bootstrap config.

Each server needs its own scope name. Pass it as a start argument:

```bash
+matchzy_config_scope cs2-server-1
```

CSM **1.7.8** and newer add this to every server's start command automatically (`<hostname>-server-<N>`), and `sudo csm doctor` fails when servers share MySQL without it. On a manual setup, add it yourself. Without it the plugin falls back to a name based on the host and game directory and logs a warning.

If you would rather not share a database, a separate SQLite file per server also works.

### Rotate your server token if you shared old logs

MatchZy-Enhanced before **1.4.28** wrote the MAT server token in plain text to server logs (`matchzy_bootstrap_token` and `matchzy_remote_log_header_value` lines). Anyone with that token can post fake match results to MAT. From 1.4.28 secrets are hidden in logs, console output and chat.

If you have posted or shared server logs from an older version, change `SERVER_TOKEN` in MAT, restart MAT, and configure your servers again from the **Servers** page.

## After any change: refresh status

After updating configs, plugins, or CS2 itself:

1. Restart the server(s)
2. Refresh servers in MAT (Servers page)
