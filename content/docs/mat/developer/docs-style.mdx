title: Docs style guide
description: Guidelines for writing operator-first docs (with advanced details separated).
---

This guide keeps docs consistent across MAT / CSM / MatchZy Enhanced.

## Default: write for operators

Operator pages should answer:

- What does this mean?
- What do I do next?

Use:

- short sections
- checklists
- copy/paste commands
- clear “If you use CSM…” callouts

Avoid:

- internal API endpoints
- event names
- parsing/implementation details
- deep protocol specifics

## Where technical details go

If something is useful but not required for a tournament admin, put it in:

- **Advanced**: deeper operational details
- **Developer**: implementation, architecture, code-level docs

Operator pages can link to advanced pages with a simple “Learn more (Advanced)” section.
