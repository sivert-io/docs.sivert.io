This page covers the MatchZy settings you use when integrating a CS2 server with MatchZy Auto Tournament (or any external controller).

## Loading a match JSON

MatchZy loads a match by fetching JSON from a URL:

- **Command**: `matchzy_loadmatch_url <url> [header_key header_value]`

The URL should point to a match JSON document (typically hosted by MatchZy Auto Tournament).

### Example

```bash
matchzy_loadmatch_url "https://mat.example.com/api/matches/my-match-slug.json"
```

If your match JSON endpoint requires a header (for example a bearer token):

```bash
matchzy_loadmatch_url "https://mat.example.com/api/matches/my-match-slug.json" "Authorization" "Bearer REDACTED"
```

## Example match JSON (copy/paste)

MatchZy validates that your payload includes these required top-level fields:

- `maplist` (array)
- `num_maps` (int)
- `team1` (object with `name` and `players`)
- `team2` (object with `name` and `players`)

### Minimal 5v5 (one map)

```json
{
  "matchid": 12345,
  "num_maps": 1,
  "maplist": ["de_mirage"],

  "team1": {
    "name": "Team One",
    "players": {
      "76561198000000001": "Player1",
      "76561198000000002": "Player2",
      "76561198000000003": "Player3",
      "76561198000000004": "Player4",
      "76561198000000005": "Player5"
    }
  },
  "team2": {
    "name": "Team Two",
    "players": {
      "76561198000000006": "Player6",
      "76561198000000007": "Player7",
      "76561198000000008": "Player8",
      "76561198000000009": "Player9",
      "76561198000000010": "Player10"
    }
  }
}
```

### Workshop maps

MatchZy Enhanced supports workshop maps **when the `maplist` entry is a numeric workshop PublishedFileId**. When the map string is numeric, MatchZy will change maps using `host_workshop_map "<id>"`.

Example (one workshop map):

```json
{
  "matchid": 12345,
  "num_maps": 1,
  "maplist": ["1234567890"],

  "team1": { "name": "Team One", "players": { "76561198000000001": "Player1" } },
  "team2": { "name": "Team Two", "players": { "76561198000000006": "Player6" } }
}
```

Notes:

- `maplist` entries that are **not numeric** are treated as normal maps and are loaded with `changelevel` (e.g. `de_mirage`, `de_anubis`, etc.).
- If you want to run a BO3, set `"num_maps": 3` and provide **at least** 3 entries in `maplist`.
- For more details (including mixing stock + workshop maps), see **[Maps (including workshop)](/docs/me/user/maps)**.

## Event webhooks (remote log)

MatchZy sends match events (webhooks) to your platform.

MatchZy Auto Tournament accepts events on:

- `POST /api/events`
- `POST /api/events/:matchSlugOrServerId`

- **Set endpoint**: `matchzy_remote_log_url "<url>"`
- **Optional header**:
  - `matchzy_remote_log_header_key "<key>"`
  - `matchzy_remote_log_header_value "<value>"`

In MAT-style setups, these values are typically configured by the platform via RCON when a match is allocated:

- `matchzy_remote_log_url "https://mat.example.com/api/events/<matchSlug>"`
- `matchzy_remote_log_header_key "X-MatchZy-Token"`
- `matchzy_remote_log_header_value "<serverToken>"`

### Server-level health events

MatchZy Enhanced also emits a **server-level health event** (not tied to a specific match):

- `event: "server_health"`
- `server_id`
- `plugin_version`
- `timestamp`
- `db_ok` (whether MatchZy can reach its SQLite/MySQL database)
- `db_type` (`"sqlite"` or `"mysql"`)
- `db_error` (last error summary; best-effort)

This is used by platforms like MAT to surface a **persistent admin warning** when backups/event queue may be impacted.

Example payload:

```json
{
  "event": "server_health",
  "server_id": "s_1",
  "plugin_version": "1.4.14",
  "timestamp": 1769805517,
  "db_ok": false,
  "db_type": "mysql",
  "db_error": "Unable to connect to any of the specified MySQL hosts."
}
```

## Demo uploads

If you record demos, MatchZy can upload them after each map:

- **Endpoint**: `matchzy_demo_upload_url "<url>"`
- **Optional header**:
  - `matchzy_demo_upload_header_key "<key>"`
  - `matchzy_demo_upload_header_value "<value>"`

MatchZy Auto Tournament accepts demo uploads on:

- `POST /api/demos/:matchSlug/upload`

Related settings:
- `matchzy_demo_recording_enabled`
- `matchzy_demo_path`
- `matchzy_demo_name_format`

## Match reports

MatchZy can upload a match report payload to your platform:

- `matchzy_report_endpoint "<url>"`
- `matchzy_report_token "<token>"`
- `matchzy_report_server_id "<server_id>"`

MatchZy Auto Tournament accepts match reports on:

- `POST /api/events/report`

You can also generate a report snapshot on demand:

- `matchzy_match_report`

## Server identity and status (for dashboards/allocators)

These values help a controller understand what the server is doing:

- `matchzy_server_id`
- `matchzy_tournament_status`
- `matchzy_tournament_match`
- `matchzy_tournament_next_match`
- `matchzy_tournament_updated`

## Bootstrap initialization (single payload)

In MAT setups, servers can be initialized using a **bootstrap URL** so the controller doesn’t have to push many separate RCON commands.

- The controller sets:
  - `matchzy_bootstrap_url`
  - `matchzy_bootstrap_token` (sent as `X-MatchZy-Token`)
- The plugin fetches a single payload and applies it locally (persisting settings in its own DB).

MatchZy Auto Tournament exposes:

- `GET /api/servers/:id/bootstrap` (server-token auth via `X-MatchZy-Token`)

The response includes a `commands[]` list which the plugin executes (webhook URL + headers, demo upload config, loadmatch auth headers, chat prefixes/core defaults, etc.).
